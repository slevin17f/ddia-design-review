# 审查流处理的时间、顺序与恢复边界

## R · 原书依据

第 11 章，PDF 物理页 416–426、437–447。可重放日志按分区保存位置。窗口按业务事件发生时间或处理时间划分会得到不同答案。故障恢复须配对输入位置、算子状态和输出效果。

## I · 如何选择

需要独立订阅或回放时，记录每组消费者在每个分区的进度及最短保留期。队列逐条确认适于分摊无次序依赖的工作。按业务键选分区，说明每个键需要的顺序。按发生时间计量时，约定窗口边界、迟到期限、超期记录去向和订正协议。状态更新、持久化位置和外部输出逐项写清事务或幂等边界。

## A1 · 从原书到演练

原书用搜索曝光与点击的配对说明两侧事件都可能先到（PDF 441–442）。合成演练：订单 A 于 10:04 发生，10:07 才送达。五分钟滚动窗口按事件时间计数，允许在窗口结束后十分钟内订正，按服务端时钟截止。A 属于 [10:00,10:05)，10:07 仍接纳，订正旧窗。消费重试再送 A 时使用相同订单事件 ID 去重；若允许订单多次变更，改用每次变更独有的事件 ID。

## A2 · 何时调用

收到队列重复、窗口迟到、CDC 回填、消费者恢复或“恰好一次”承诺时使用。跨越客户端到真实扣款、发货等效果的证明，衔接端到端卡。

## E · 执行与验收

1. 绘出来源、分区键、处理状态、接收端。CDC 首次同步须对齐一致快照与变更日志位点；确认日志在追赶期间仍可读。
2. 分别列出到达顺序和事件发生顺序，说明迟到会丢弃、追加修订还是冲正。缺少时钟误差与等待期限时，保留“窗口尚可能改变”。
3. 选择与下游一致的写入方法。若结果可覆盖，按窗口键和单调版本更新；若为增量累加，在同一事务内登记事件 ID 并累加。检查点须能恢复配套状态；发送外部通知时单列接收方去重能力。
4. 分别在输出成功但位点未保存、恢复后迟到、保留期已过三处推演。给出恢复起点、可能重复或遗漏的记录和处置办法。无法追溯已过期区间时明确缺口，转快照或归档重建。

## B · 反例与判停

同一事件在两个分区的 offset 不可直接比较。水位线表达进度估计，无法证明以后绝无更早事件。重放期间若关联会变化的“当前”维表，必须声明所用维表版本，否则重放可产生另一种业务结果。
