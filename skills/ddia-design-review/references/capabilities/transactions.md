# 用两个并发事务检验业务约束

## R · 原书依据

第 7 章，PDF 222–231 页讨论读提交、快照与读倾斜，231–238 页分析更新丢失、写倾斜和幻读，239–251 页比较串行执行、两阶段锁及可串行化快照隔离。

## I · 判断方法

先把约束写成每次提交后必须成立的布尔条件，再列读谓词和写集合。相同对象的读改写可能丢更新；不同对象上成功的两次写也可能破坏共同读过的谓词。快照能固定一次事务看见的历史，同时允许两个事务各自依据旧快照提交。

## A1 · 合成演练

机房的 A、B 两条链路都在线，要求至少保留一条。T1 与 T2 都从同一快照数出 2，T1 关闭 A，T2 关闭 B；两者修改不同行且都提交时，在线数变为 0。采用真正可串行化的事务，允许中止并从头重试；也可将每个机房的守卫行预先创建，并让所有改动者先在同一事务中锁住它再以能看见前一提交的读重新核对。第二个请求须拒绝下线或中止后重读并拒绝。

## A2 · 何时调用

评审库存、名额、唯一约束、余额转账或报表的一致视图时使用。跨库提交的中途故障另查一致性与共识卡。

## E · 执行与验收

1. 列每个事务的快照、读谓词、目标行及提交点；给出两个正常串行顺序，再尝试构造两个顺序都不可能产生的观察结果。
2. 单记录计数优先核查原子增量或比较并交换的条件；跨行谓词要说明如何覆盖新增的匹配行。仅锁已找到的行，不能覆盖原本空的查询结果。
3. 记录实际数据库的隔离语义、冲突检测范围、中止处理和重试边界。重试从事务开头重新读；邮件等外部副作用需单独处理。
4. 交付“约束／最小反例／选用机制／冲突时返回／验证历史”。成功标准是每条允许的提交历史都维持指定约束，验收样例中第二个并发请求结果明确。

## B · 边界

SQL 隔离名称在产品间有差别。一个反例足以推翻保证；单次交错模拟通过不足以证明数据库实现正确。
