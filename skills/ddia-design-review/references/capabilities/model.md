# 用读写路径选择数据模型

## R · 原书依据

第 2 章，PDF 39–49、55–61 页。按简历整份读取时，局部性有利于文档模型。推荐人、共同雇主等关系让独立实体重新进入查询。跨可变层级的地区查询展示了图遍历的适用条件。

## I · 判断方法

标注实体何时独立变化、关系基数、常用查询要走几跳、查询深度是否预知。整份读写的有界树可先试嵌套。共享实体与组合过滤可先试引用加联结。关系本身参与可变深度路径查询时，比较图遍历与递归关系查询。

## A1 · 合成演练

课程目录中，课程独有的教学单元随课程整份展示；每位讲师可教多门课程且随时改名。初稿把讲师名复制进 200 门课程。改为课程保存讲师 ID，讲师资料有一个权威记录，课程和讲师以关联表表达多对多。单元有界且独占时可嵌入课程。若业务要求证书保留签发时姓名，签发快照需独立保存，不能随当前讲师更名而变化。

## A2 · 触发与相邻问题

当团队比较关系、文档或图模型，或发现一处修改必须改许多对象时调用。数据布局定了以后，索引、页读写与扫描代价交给存储卡。

## E · 执行与验收

1. 要求一条主读取、一条跨实体查询、一次共享信息修改，列出实体、稳定 ID、关联的方向及最大规模。
2. 用相同样例分别画两种候选表示。沿每条操作写下读取对象、联结条件、更新范围和重复副本的同步机制。
3. 若复制展示数据，标出权威来源及允许的陈旧时间。若文档持续增长，给出尺寸、部分读取或整体重写的测量。若路径长度可变，用不同深度的输入重跑查询。
4. 输出操作对照表、所选模型、成立条件及反例。用一个多对多关系及一次更名验证不会漏写、错连或篡改历史。

## B · 判停

单个 API 返回 JSON 只能说明传输形状。缺少更新路径或关系规模时，保留备选并注明应补哪条查询。原书的产品能力描述有版本背景。
