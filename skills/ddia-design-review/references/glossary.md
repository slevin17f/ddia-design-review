# 用一次观察区分相邻术语

| 术语 | 评审时怎样识别 | 章 |
| --- | --- | --- |
| 延迟百分位 | 在一个明确的请求群与时间窗内排序。p99 对应约 99% 的请求耗时不超过的值。高扇出请求还要量用户可见的总耗时。 | 1 |
| 数据局部性 | 一次访问需要的字段能否一同取回。整份文档只读一小部分时，测实际读出的字节数。 | 2 |
| 写放大 | 用存储介质写入量与逻辑写入量之比衡量额外写入。在包含压实或索引维护的窗口取数。 | 3 |
| 向后／向前兼容 | 新代码能读旧数据／旧代码能读新数据。滚动升级中可能同时需要两者。 | 4 |
| 读己之写 | 完成写入的用户随后读取时能看见自己的更新。跨设备也要界定用户身份。 | 5 |
| 单调读 | 同一读者一旦见到较新版本，后续读不会倒退。第一次读取仍可能陈旧。 | 5 |
| 因果顺序 | 若回复依赖原消息，观察者应先见到原消息。在没有因果依赖的并发事件间还有排序自由。 | 5、9 |
| 分区／复制 | 分区决定某条数据归哪一组，复制决定这组数据保存几份。增加副本数和拆分热键会改变不同的瓶颈。 | 5、6 |
| 写倾斜 | 两个事务各自根据同一约束读到的旧值，写不同记录，合并提交后违反约束。 | 7 |
| 可串行化 | 所有已提交事务的结果可以解释为某个串行顺序。检查跨记录读写依赖。 | 7 |
| 线性一致性（可线性化） | 每次操作仿佛在调用与返回之间某一瞬间生效，遵守已完成操作的实时先后。 | 9 |
| 安全性／活性 | 前者可由一次坏结果推翻，后者关心条件恢复后工作能否最终完成。 | 8、9 |
| 事件时间／处理时间 | 事情发生的时间和处理器见到它的时间。晚到会令按发生时间分窗的已发结果需要更正。 | 11 |
| 偏移量 | 某一日志分区内的位置。恢复时还要对齐算子状态和已产生的输出。 | 11 |
| 派生数据 | 从其他输入经转换得出的索引、缓存或视图。重建要求保有足够输入、历史及相应规则版本。 | 10–12 |
| 幂等 | 同一逻辑操作重复执行，观察到的目标效果与执行一次相同。分别检查业务表、消息和外部服务的效果。 | 11、12 |
