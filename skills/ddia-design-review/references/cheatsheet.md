# 决策规则速查 — 数据密集型应用系统设计（2018 年中译本）

| 能力 | 一句话规则 |
|---|---|
| 建立负载与服务目标 | 量化最忙租户或最热路径，写出可比较的延迟与资源预算。 |
| 由访问路径选择数据模型 | 用两条常用查询和一次关系变更验证模型。 |
| 选择存储与索引结构 | 比较点查、写入与扫描的代价，写出能推翻选择的基准负载。 |
| 验证新旧读写兼容性 | 用版本矩阵跟踪默认值、未知字段与数据重写。 |
| 选择复制与会话保证 | 沿一次写后读标出各副本的位置和可接受的陈旧程度。 |
| 估算热点和跨分区成本 | 按键分布及查询范围估算扇出并检查迁移期间的路由。 |
| 验证事务隔离能否保持不变量 | 构造两笔并发事务，追踪读集、写集和允许的提交结果。 |
| 判断超时与过期持有者 | 枚举不可区分的故障历史，检查谁能拒绝过期写入。 |
| 界定顺序和协调范围 | 写明哪一项决策需要全局同意，以及失去多数派时如何响应。 |
| 设计可重跑的批计算 | 检查输入快照、连接数据移动、任务重试及发布边界。 |
| 处理乱序、重放和重复交付 | 分别追踪输入位置、算子状态和输出副作用。 |
| 审阅跨系统正确性与数据责任 | 沿用户操作追到最终效果，规定证据、纠错和责任人。 |

> 速查只给结论；需要原文依据、案例或反例时读对应能力卡。
